# 发票视频识别系统

基于 FastAPI + PaddleOCR 的增值税电子发票识别系统，支持通过手机摄像头采集发票数据，PC 端实时查看汇总。

## 功能特性

- **双端协作**: PC 端查看汇总，手机端通过摄像头采集
- **双重识别**: 二维码解析和 OCR 文字识别互补，确保识别准确
- **区域定位**: 针对电子发票标准版式优化，精确定位关键字段区域
- **实时同步**: 基于 WebSocket 的多端数据实时同步
- **数据持久化**: 本地 SQLite 数据库存储
- **一键汇总**: 自动计算价税合计金额

## 技术栈

### 后端
- **FastAPI** - 高性能 Web 框架
- **PaddleOCR** - 飞桨 OCR 文字识别
- **OpenCV** - 图像处理和二维码检测
- **WebSocket** - 实时通信
- **SQLite** - 本地数据存储

### 前端
- **原生 HTML/CSS/JS** - 无依赖，轻量级
- **MediaDevices API** - 摄像头调用
- **WebSocket Client** - 实时数据更新

## 快速开始

### 1. 安装依赖

```bash
# 创建虚拟环境
python -m venv venv
source venv/bin/activate  # Windows: venv\Scripts\activate

# 安装依赖
pip install -r requirements.txt
```

### 2. 启动服务

```bash
# 方式一：直接运行
python -m backend.main

# 方式二：使用 uvicorn
uvicorn backend.main:app --host 0.0.0.0 --port 8000 --reload
```

服务启动后访问:
- **PC 端**: http://localhost:8000
- **手机端**: http://localhost:8000/mobile

### 3. 使用说明

1. **PC 端**: 打开浏览器访问系统，查看发票汇总列表
2. **手机端**: 扫描 PC 端显示的二维码或直接输入手机端地址
3. **采集**: 将手机摄像头对准发票，点击拍照
4. **识别**: 系统自动识别发票号码、开票日期、价税合计
5. **同步**: PC 端实时显示识别结果和汇总金额

## 识别逻辑

### 识别流程

1. **同时执行**二维码解析和 OCR 识别
2. **合并结果**：
   - 发票号码：二维码优先，OCR 补充
   - 开票日期：二维码优先，OCR 补充
   - 价税合计：二维码优先，OCR 补充
3. **数据验证**：金额范围检查、日期格式验证

### 二维码格式解析

电子发票二维码标准格式：
```
01,发票代码,发票号码,开票日期,校验码,金额
```

| 字段位置 | 字段名 | 格式 | 示例 |
|---------|--------|------|------|
| 1 | 版本号 | 固定值 | 01 |
| 2 | 发票代码 | 10-12位数字 | 1234567890 |
| 3 | 发票号码 | 20位数字 | 25312000000432294815 |
| 4 | 开票日期 | 8位数字(YYYYMMDD) | 20251226 |
| 5 | 校验码 | 可选，20位数字 | ... |
| 6 | 价税合计 | 可选，带小数 | 128.50 |

### OCR 区域定位

针对电子发票标准版式进行区域定位：

| 区域位置 | 识别内容 | 方法 |
|---------|---------|------|
| 左上角二维码 | 发票号码、日期、金额 | 二维码解析 |
| 右上角区域 | 发票号码、开票日期 | OCR 文字识别 |
| 底部区域 | 价税合计 | OCR 文字识别 |

## 常见问题

**Q: 识别失败怎么办？**
A: 确保发票图片清晰、光线充足，二维码完整可见。系统会同时使用二维码和 OCR 两种方式识别。

**Q: 为什么识别的金额不对？**
A: 请检查二维码是否包含金额信息（第6字段）。如二维码不含金额，系统会自动使用 OCR 识别底部金额区域。

**Q: 手机无法访问 PC 端服务？**
A: 确保手机和 PC 在同一局域网，使用 PC 的局域网 IP 访问（如 http://192.168.1.100:8000）。

**Q: 数据存储在哪里？**
A: 数据存储在 `data/invoices.db` SQLite 数据库文件中。

**Q: 发票号识别错误？**
A: 系统会优先使用二维码第3位（20位）作为发票号。如二维码格式不符，会使用 OCR 识别右上角区域。
